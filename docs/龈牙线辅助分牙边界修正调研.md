# 龈牙线辅助分牙边界修正调研

调研日期：2026-10-12。范围为分牙展示前的自动边界修正。本文为代码检查、已有输出统计和公开技术资料调研，尚未实现新修正管线，也未完成修正效果的浏览器验证。

## 结论

推荐在已有标签加载或在线推理完成后，增加“标签小岛检查 → 共享边界提取 → 受限贴面平滑 → 连续曲面路径构建 → 边界局部三角面细分 → 区域赋标签 → 验证 → 展示”。

关键是将平滑线转成真正的网格分区。只画绿线不会改变分牙结果；只把平滑线附近的原始顶点重新分类，边界仍受原三角网格分辨率限制。整颌平滑会改变牙冠表面，不适合解决本问题。

第一版同时处理牙齿—牙龈和牙齿—牙齿接口。前者改善牙颈边界，后者改善相邻牙间分界。二者共同组成完整单牙轮廓。

## 当前实现与根因

- `src/segmentation.mjs::labelGeometry` 将离散标签直接转为顶点 RGB。混合标签三角形内没有明确的区域归属，颜色由渲染插值过渡。代码检查能确认这一机制，但本次没有直接观察用户所指毛刺的截图，具体病例需在实施时定位。
- `src/main.ts::addBuffer` 解析模型、以 `0.00001` 容差合并顶点计算法线，再展开三角面；本地 JSON 随后直接进入上色。
- `src/main.ts::runSegmentation` 取得在线标签后也直接上色。
- `src/main.ts::segmentationReady` 当前以 `teeth` 存在判断准备完成，没有边界修正状态。
- `src/model-import.mjs` 中 `add(...)` 是同步调用；如果修正改成异步，必须改为等待结果，并在等待之后重新核对 generation，防止切换病例后旧任务提交模型。
- 当前 `Model` 不保存原始标签、来源映射和修正结果。后续需要分别保留，不能只留颜色数组。

“网格边界锯齿”“小标签岛”“错误解剖分界”需要分别诊断。平滑能抑制前两类的一部分问题，不能纠正整片错牙号或恢复缺失的真实牙颈信息。

## 旧龈牙线算法能复用什么

来源为 `../初始位预处理/scripts/generate_gumlines.py`。

1. `clean_enclosed_islands`：按表面积清理仅被一种其他标签包围的小连通域；保护扫描开放边和非流形边；不是删除所有小区域。
2. `extract_interfaces`：跨标签边中点作为节点；两标签面连接两个节点；三标签面用重心形成共享交汇点。每个标签对只存一份接口。
3. `trace_chains`：在端点和分叉拆链，不擅自补缺口。
4. `smooth_chain`：细分、邻点平滑、投影回原网格、限制相对原锚点的移动，固定开放曲线端点。
5. 来源面编号和重心坐标，可以作为新生成顶点的来源追踪基础。

缺口是 `smooth` 只有投影采样点，不是沿三角面的连续嵌入路径；未检测自交、跨曲线交叉，也未输出按曲线重分区的网格。三叉点必须保持全局唯一，并增加多条曲线联合检查。

现有参数为采样间隔 0.25、最多移动 0.3、8 次平滑；实验的小岛面积阈值为 1。单位都是原模型单位，不能直接标成毫米。新流程应先记录局部网格边长和单位信息，再验证参数适用性。

## 实施算法

### 1. 建立独立计算网格

输入定义为 `positions + indexed faces + labels + source mapping`，保留原坐标和上下颌位置。

OBJ 优先直接保留原顶点索引、三角化顺序和标签，不从焊接后的显示网格反推。尤其需要验证 OBJ 多分组经过 OBJLoader 合并后的面顺序与原始映射是否一致。

STL 与在线结果为展开顶点，重建拓扑时保留 corner-to-vertex 映射。重合坐标若带冲突标签，需明确诊断和归并策略，不能任取第一项。接近但未连接的两片扫描面不能因宽容差焊接到一起。退化面、非流形边和开放边先标记。

### 2. 小岛清理与局部边界带

复用受保护的小岛清理。保留原标签与变更记录。

按每一共享标签对提取接口，在原网格邻接图上构建有限宽度的边界带；边界带外的区域标签固定。参数优先按局部边长设置，并用实际病例验证。不能让牙间接触区域中空间很近但曲面上很远的位置互相吸附。

### 3. 受限曲线平滑

复用旧程序作为基线，增加局部面片投影约束。全局最近点可能跳到相邻牙面；候选投影只在当前曲线对应的连通边界带内选择，并核对路径连续性。

共享三叉点和开放端点固定，各条边界只计算一次。小环先诊断其标签和拓扑，不能仅因长度短就删掉。每轮限制边界位移，拒绝引入自交、跨线交叉和新的标签邻接。

### 4. 将线嵌入原三角曲面

这是新增核心。相邻投影点不能直接用空间直线连接。

- 同一来源面内直接用重心坐标表示线段。
- 跨面时在连通的局部边界带中寻找面带，以局部展开或曲面路径追踪产生经过各个面的路径；输出每一个穿越原网格边的交点。
- 限制路径偏离原接口的距离，拒绝跳面、穿越其他边界或绕过三叉点。仅用原网格顶点最短路会重新引入锯齿，不能作为最终分界。
- 每个交点用“原边 + 边参数”统一编号；同一边两侧使用同一组交点，公共节点只存一次。
- 曲线跨越扫描孔洞或无法形成合法面带时，回退该局部边界并报告原因，不能自动跨空白补线。

### 5. 沿曲线细分与赋标签

在每个被路径穿过的原三角面内部，用重心坐标构建二维局部坐标。把面边界、全部曲线段和交汇点作为约束，进行局部三角化。没有被穿过的面保持原样；被插入边交点的相邻面也必须同步细分，避免 T 接点。

新三角面必须完整覆盖原面，彼此不重叠。新增顶点严格由原面重心坐标还原到三维，保持原扫描的分片线性表面。细分改变拓扑，不应移动原牙冠顶点。

将嵌入边界作为区域屏障，在新面邻接图中由边界带外固定标签种子传播标签。每个区域必须有唯一、无冲突的种子；小区域无种子、开放边界导致串区或种子冲突时拒绝该修正。原始标签只作区域归属证据，不能逐个子面多数投票，否则可能再次产生锯齿。

牙龈—牙齿、牙齿—牙齿共用同一分区。三叉附近一次性三方切分，不分别生成三个互相重叠的牙冠。

### 6. 展示和持久化数据

输出建议包含 `refinedPositions / refinedIndices / faceLabels / interfaces / sourceFaceIds / barycentric / originalLabels / diagnostics`。

显示时按面标签给三角面的三个角设置相同 FDI 颜色，让颜色边界准确落在嵌入曲线上；边界两侧显示顶点可重复，计算拓扑仍共享。法线从原表面插值，不能因分类边界制造几何硬折痕。牙号中心使用修正后面片面积加权，避免细分密度改变锚点。

新顶点改变了数量，所以仅输出与旧 OBJ 同长的 `labels` JSON 无法完整表示修正结果。可以附带原顶点的新标签用于兼容，但实际展示和未来单牙导出必须采用新的分区数据。

## 方案比较与公开资料

| 路线 | 对本问题的适用性 | 建议 |
| --- | --- | --- |
| 平滑线叠加 | 不更新区域归属，原毛刺仍存在 | 仅作诊断 |
| 邻域多数投票 / 最近曲线重标原顶点 | 可清理部分噪点，但边界仍受原网格限制，近邻牙面易串标签 | 不作为最终方案 |
| 图割优化标签 | 可利用预测概率和几何邻接抑制噪声；输出仍需边界嵌入才能形成细腻分界 | 后续增强 |
| 平滑共享曲线 + 连续曲面路径 + 局部细分 | 直接复用已有龈牙线，更新真实区域，保留原扫描面 | 第一版推荐 |
| 平滑多标签标量场 + 等值界面切分 | 共享标量场可以统一处理多标签，但不保证精确经过旧平滑线，需要另建求解器与约束 | 原型对照路线 |

MeshSegNet 官方后处理用预测概率构造 unary，用相邻面法线与位置构造 pairwise，再调用多标签图割。当前本地 JSON 和在线适配只返回硬标签，没有概率，因此不能原样移植概率项，也不建议为边界显示更换整个预测模型。[官方后处理源码](https://raw.githubusercontent.com/Tai-Hsien/MeshSegNet/master/step6_predict_with_post_processing_pygco.py)

Trimesh 最近点接口返回表面点、距离和来源三角面，支持旧程序的来源映射；该接口不是连续曲面路径生成器。[官方 proximity 文档](https://trimesh.org/trimesh.proximity.html)

CGAL 的二维约束 Delaunay 三角化支持插入约束线段，可作为“单个原面内局部三角化”的参考或可选内核；还需自行构建跨面路径、标签传播和来源映射。它不是开箱即用的牙齿分割功能，采用其实现前需核对相关包许可和 Windows 构建依赖。[官方接口](https://doc.cgal.org/latest/Triangulation_2/classCGAL_1_1Constrained__Delaunay__triangulation__2.html)

libigl 提供曲面测地距离相关工具，可用于曲面局部邻域和路径算法选型，但不能把沿原网格边的 Dijkstra 路径等同于无锯齿的连续曲面线。[官方教程](https://libigl.github.io/tutorial/#exact-geodesic-distance)

## 集成与运行选择

先以本机 Python 做离线原型，复用 NumPy、SciPy、Trimesh，与旧输出对比。这是最小重复开发的验证路线；完成后根据耗时选择运行部署。

- 本地服务路线：新增纯本机 `/api/segmentation/refine`，本地文件夹和在线标签都进入同一修正核心。不调用 SSH 或远端推理。需要将启动脚本与本机依赖一起打包，否则现有仅运行 Vite 的文件夹导入会失效。
- 浏览器路线：移植为 Web Worker，使用 TypedArray 和 transfer，不依赖本地服务；几何追踪、投影索引与三角化的移植工作较多。是否优先做这条路线取决于原型结果和部署要求。

旧文件记录的完整生成耗时约 11–37 秒，包含诊断和文件输出，不是 Worker 或完整新管线的性能预测。不能在主线程同步执行。新流程先显示原始预处理模型，顶部“分牙”持续忙碌，所有模型的修正和验证完成后才允许进入。

本地与在线入口都调用统一 `prepareSegmentation`，最终提交网格和牙号前再次核对任务代次。切病例、移除模型、改颌面均取消/作废旧任务。计算失败应明确显示失败或局部回退状态；不得将未修正结果标成修正成功。

保留源几何与细分几何两份：预处理展示及重新推理使用源几何，分牙展示使用细分几何，避免重试推理时标签与新顶点数量错配。回退区域从共享原接口构造分区，必须在面边界处与成功区域一致。

## 实施顺序与验收

1. 选取已有无明显托槽上颌、下颌开放轮廓、带小岛与多环样本，定位实际毛刺。先做未平滑共享接口的分区基线，区分颜色插值与标签本身的问题。
2. 对一个模型做平滑曲面路径与局部细分原型，输出原始、未平滑分区、平滑分区三组。重点验证三叉点、局部环、边交点同步与区域传播。
3. 通过几何验收后接入两条异步数据流和入口忙碌状态，再做实际界面侧面、咬合面及牙间近景比较。
4. 扩大到已有本地病例，逐病例记录失败和回退，不以少量样本的闭环率代替全量结果。

几何验收必须包括：逐原面面积覆盖、无重复子面、无 T 接点、来源重心坐标重建、边界连续与无自交、共享接口两侧一致、原顶点/共同坐标不变、边界位移限制、边界带外标签不变、牙位不丢失。非流形和开放扫描输入单独统计，不能要求所有原始牙位无条件闭环。

效果指标用等弧长采样后的转角或曲率、长度、双向曲面边界距离、每牙区域面积变化和连通域变化，并配合相同相机/光照的近景截图。阈值需先由样本定标；目前没有专家标注，不能宣称真实分牙准确率提高。

性能记录上下颌分别及整病例的耗时、增面比例、峰值内存和取消响应。接入后执行项目规定的 `npm.cmd test`、`npm.cmd run build`；若新增本地服务则增加对应服务测试；渲染改动需要浏览器验证。当前调研未修改运行代码。
