# STL Studio · 牙模可视化工具

参考牙模查看页面的可视化工具。顶部步骤栏、浅灰画布、沙金色牙模、标准视角，可同时查看多个 STL / OBJ。使用 TypeScript、Vite、Three.js。默认在浏览器读取本地文件夹中的模型和已有分牙结果。单独上传未分牙模型时，可经本机 Python 适配服务和 SSH 调用客户 AI 牙科服务器的现有 Docker 容器。

## 启动

需要 Node.js 20.19+ 或 22.12+。

```powershell
cd "D:\工作\CYY\AI口腔\瑞通\排牙软件\STL可视化工具"
npm.cmd ci
npm.cmd run dev
```

打开 http://127.0.0.1:5186 。默认进入“模型预处理”的上传页面，不自动打开固定病例。点击“选择数据文件夹”读取整个数据目录及已有分牙 JSON；也可在空白页面点击“单独上传 STL / OBJ”或拖入模型，使用在线自动分牙。刷新后需重新选择文件夹或文件。

也可双击 `start.cmd` 启动，首次运行会安装依赖。

## 使用

- 顶部步骤依次为模型预处理、分牙、初始位模型、治疗计划、目标位、分步、附件。目前实现模型预处理和分牙，其余步骤显示“该功能还在开发中”。
- 咬合碰撞、模型调整仅提供开发中占位页面。切换步骤后返回模型预处理会保留已上传的模型、视角及网格状态；分牙入口会执行下述龈牙线强平滑处理。
- 默认无网格时使用 35° 视场角的透视投影。点击顶部“网格”开启正交投影及屏幕朝向的参考方格，再次点击恢复透视投影。切换保留观察方向、中心和目标平面的显示比例，不修改模型坐标；不同深度的牙齿会因投影变化而呈现不同的相对大小。
- 网格参照截图设计为浅灰细线与浅红粗线，覆盖画布及牙模；小格 1、大格 10 个模型坐标单位，不能自动认定为毫米。格线随正交缩放改变间距，过密细线会淡出。右下角标明投影模式与网格单位，导出 PNG 时包含已开启的网格。
- 左键拖动旋转，右键拖动按屏幕方向平移，中键拖动或滚轮缩放。滚轮向前放大。触屏单指旋转、双指缩放和平移。
- 采用固定竖直轴的环绕操作，旋转围绕可见模型中心；限制极点防止画面翻转，轻微阻尼平滑收尾。水平拖动从顶部视角仍围绕统一竖直轴旋转。
- 上颌面、正面、右侧、仰视、左侧、后视、下颌面按钮切换视角。上下颌面保留极小倾角以避免极点奇异。
- “全颌”筛选上颌或下颌；每个图层可独立显隐、移除；单独上传模式可修改所属颌面，文件夹模式的颌面由文件名确定。文件名含 upper/maxilla/上颌 或 lower/mandib/下颌 时自动分类；其他文件需手动指定。
- 拖入一个或多个 ASCII/二进制 STL 或 OBJ，或在空白页面点击“单独上传 STL / OBJ”，支持混合选择。每次上传替换当前整批模型，同时选择的上下颌文件会一起保留；取消文件选择不影响当前模型。单文件最大 150 MB；读取失败显示提示并继续处理本批其余文件，全部失败时回到上传页面。上传成功后切换至全颌显示。连续上传时仅显示最新一批，旧批次未完成的读取不会重新加入场景。
- OBJ 文件内的多个网格分组归入同一图层，并保留原始坐标。支持三角面、多边形面和负索引；忽略点、线、MTL 材质和纹理，统一使用沙金色材质，不读取外部资源。只有点或线、不含表面的 OBJ 会提示无法显示。
- 平滑、原始面片和线框显示，透明度调节，Y/Z 向上选择，以及三轴 90° 旋转。方向操作对所有模型整体应用。
- 底部支持适应窗口（F）、恢复初始视图、导出 PNG 画布截图；右上角可以隐藏模型面板。

模型保留原始坐标及上下颌咬合关系，不单独居中。默认输入坐标 Z 向上、前牙朝 -Y；其他模型可调整整体朝向。STL / OBJ 没有可靠的标准单位信息，界面尺寸使用原始坐标单位，不能自动认定为毫米。透明模型交叠可能出现实时渲染排序误差。

## 从本地文件夹读取已有分牙结果

在预处理点击“选择数据文件夹”，选择工作区 `排牙软件/data/瑞通平台自有数据` 整个目录（相对项目根目录为 `../data/瑞通平台自有数据`），也可以选择其中单个病例或 `obj` / `stl` 子目录。浏览器在本机读取模型和标签，交给本地 Python 服务执行龈牙线强平滑；文件夹模式不会请求线上推理。请用 `start.cmd` 一起启动前端与本地服务。

文件以 `_upper.obj` / `_lower.obj` 或 `_upper.stl` / `_lower.stl` 命名，并与同目录、同名 `.json` 配对。优先使用有完整结果的 OBJ；没有完整 OBJ 配对时可使用 STL。忽略 `_ul` 合并模型、`_only_tooth` 及 basics 文件，避免重复加载。选择数据总目录时，左上角提供病例切换，每次只显示一个病例的上下颌。

读取期间顶部“分牙”转圈，模型与标签校验完成后才允许进入。预处理保留原始网格和沙金色，分牙页面显示强平滑后的 FDI 区域及固定牙号气泡。缺失、损坏、无牙齿或顶点数量不匹配的结果显示具体错误，并阻止进入分牙；不会自动改用线上推理。文件夹模式的颌面根据文件名确定，不能手动修改。切换病例会清除旧模型，过期异步读取不会覆盖新病例。

空白页面保留“单独上传 STL / OBJ”入口，以下在线自动分牙仅适用于此入口或单文件拖入。

## 自动分牙

先启动本地适配服务，再启动前端。本机需要 Python 3.11+、`server/requirements.txt` 中的依赖和可免密访问客户服务器的 OpenSSH；GPU 和模型依赖使用服务器容器已有环境。

```powershell
python -m venv --system-site-packages .venv
.\.venv\Scripts\python.exe -m pip install -r server/requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app:app --app-dir server --host 127.0.0.1 --port 5187
```

也可双击 `start-inference.cmd`。前端开发/预览服务器将 `/api` 转发至 5187；生产部署需为同源 `/api` 配置反向代理。SSH 使用当前用户已配置的 `AI牙科客户服务器` 主机别名，认证信息不写入项目。

1. 在预处理上传上下颌 STL / OBJ。文件名无法判断颌面时，在模型面板手动指定上颌或下颌。
2. 上传完成后自动在后台依次调用 FPS 与 BDL 两阶段推理，顶部“分牙”步骤转圈，期间不能进入分牙界面，预处理视图仍可旋转和缩放。所有模型推理和强平滑完成后，顶部“分牙”步骤才可点击。失败时在预处理页面显示原因和重试入口；颌面未知时自动打开模型面板，指定完成后自动开始分牙。成功结果保留到本次模型被替换为止。重新上传会丢弃旧结果，旧请求不能给新模型着色。
3. 牙龈保持沙金色，牙齿按 FDI 牙号着色。11/31 使用同一套浅色，21/41 使用同一套深色，沿中切牙到后牙依次为蓝、紫、粉、绿、青、橙、蓝紫。点击“牙号”显示蓝色圆形标注和引线。气泡位置在模型坐标中固定，随模型旋转、平移和缩放，保持朝向屏幕；不做碰撞避让或贴边重排，允许重叠，颌面筛选仅控制显隐。气泡、文字、锚点和引线在三维场景中绘制，与牙模共用深度缓冲；牙模会遮挡后方的标注，包括气泡及引线的局部遮挡。
4. “调整分牙”为占位按钮，暂不执行编辑。返回预处理恢复沙金显示，切回分牙复用已完成的推理结果。推理失败显示原因并提供重试。

适配层默认通过 SSH 调用 `tooth-3d` 容器的 `/opt/conda/envs/tgn/bin/python`，使用 `/home/yidong/ai-dental-orth/pathology_analysis/inference` 现有代码及 `models/ckpts/fps.h5`、`bdl.h5`。可通过 `DENTAL_SSH_HOST`、`DENTAL_CONTAINER`、`DENTAL_REMOTE_PYTHON`、`DENTAL_MODEL_ROOT` 环境变量修改配置。

现有 HTTP API 包含整套病理分析及持久化流程，没有独立模型上传分牙接口，因此本适配层直接调用容器现有 FPS/BDL 管线，只取分牙结果。执行代码经 SSH 命令传递，不安装远程文件、不修改源码、不重启线上服务，也不写入病例库或 MinIO。模型顶点压缩后通过 SSH 标准输入传输，临时 OBJ 在请求完成后删除。

输入保持原始坐标及训练所用牙模方向，预处理里的视图朝向操作不重写原始坐标。模型输出通过坐标匹配映射回每个上传三角面顶点，并校验匹配误差。样例实测完成上下颌推理，但牙号和边界的准确性仍由现有模型决定；强平滑用于修正边界毛刺，不用于判断牙号或纠正牙齿识别。每次请求在容器中加载权重，最多等待 10 分钟；同一个本地适配服务串行执行推理，多个本地适配实例仍可能同时使用远端 GPU。

分牙版本在 `dev-fenya`；咬合碰撞及整颌调整单独保存在 `dev-yaohe`。阶段改动与验证记录见 [分牙阶段交接说明](docs/segmentation-handoff.md)。

## 龈牙线强平滑模块

本地标签与在线推理共用 `server/refinement/` 模块。在原始标签上清理小型封闭孤岛，提取牙龈/牙齿和牙间共享边界，将平滑线投影回原始牙面，求解边界带内的标签场，最后在原三角面中重新划分区域。参数复用已确认的强平滑：带宽 1.2、场平滑权重 6、曲线约束权重 16、曲线迭代 48、位移上限 0.55、孤岛面积上限 1。长度和面积均按原始模型单位计算。

`src/segmentation-refinement.mjs` 管理原始 OBJ 拓扑、二进制传输、面片着色和按面积计算牙号锚点。分牙展示独立修正网格，返回预处理使用原始网格；后续重新推理仍发送原始模型。不会写回上传文件或保存病例数据。

服务在本机串行处理强平滑，不调用 SSH。真实牙模每颌约需 1–2 分钟，期间可操作预处理视图，分牙入口保持忙碌。切换病例或重新上传会取消前端旧请求并忽略过期结果；已开始的 Python 运算会完成，之后处理新请求。服务不可用或几何检查失败会阻止分牙展示并提供重试。

修正前自动过滤叉积模长不超过 `1e-15` 或含长度不超过 `1e-12` 的边的退化三角面，并同步移除无面引用的顶点、重映射面索引和顶点标签。保留有效顶点原始坐标，不写回原始模型。过滤后无有效面或某个非零牙号完全丢失时才拒绝继续；无效坐标、索引和标签仍会报错。返回报告中的 `input_faces`、`filtered_degenerate_faces`、`input_vertices`、`removed_unreferenced_vertices` 记录清理数量，`source_faces` 为过滤后的有效面数。

`start.cmd` 自动创建独立 `.venv`、首次安装依赖并在后台启动 5187 服务，日志在 `service.log` / `service-error.log`。手动运行 `npm.cmd run dev` 时需要另启动上述 Python 服务。生产部署也需要本地处理服务和 `/api` 反向代理。算法仅对分牙边界进行几何修正，不包含解剖真值或临床准确性验证。
