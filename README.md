# STL Studio · 牙模可视化工具

参考牙模查看页面的可视化工具。顶部步骤栏、浅灰画布、沙金色牙模、标准视角，可同时查看多个 STL / OBJ。使用 TypeScript、Vite、Three.js。默认在浏览器读取本地文件夹中的模型和已有分牙结果。单独上传未分牙模型时，可经本机 Python 适配服务和 SSH 调用客户 AI 牙科服务器的现有 Docker 容器。

## 启动

需要 Node.js 20.19+ 或 22.12+。

```powershell
cd "D:\工作\CYY\AI口腔\瑞通\排牙软件\STL可视化工具"
npm.cmd ci
npm.cmd run dev
```

打开 http://127.0.0.1:5186 ，先进入标题为“研发测试工具”的登录页面。账号由本机未纳入 Git 的 `.env.local` 中 `VITE_LOGIN_USERNAME` 和 `VITE_LOGIN_PASSWORD` 配置，修改后需重启开发服务或重新构建。同一标签页刷新保留登录状态，关闭标签页后重新登录；浏览器禁用会话存储时，每次刷新需要登录。未配置账号时阻止登录并提示联系管理员。

登录成功后进入“模型预处理”的上传页面，不自动打开固定病例。点击“选择数据文件夹”读取整个数据目录及已有分牙 JSON；也可在空白页面点击“单独上传 STL / OBJ”或拖入模型，使用在线自动分牙。刷新后可重新加载预载数据，或选择文件夹、文件。

登录为静态前端的研发测试访问门槛，配置会进入浏览器构建产物，不提供后端 API 鉴权。生产访问控制需要服务端认证。部署时需要在构建环境单独配置账号。

也可双击 `start.cmd` 启动，首次运行会安装依赖。

### Linux 启动

需要 Bash、Node.js 20.19+ 或 22.12+、Python 3.11+（含 venv/pip）及 util-linux 的 `setsid`。在项目目录运行，脚本也支持从其他目录调用，路径可包含中文或空格。

```bash
bash start.sh
```

首次运行自动执行 `npm ci`，创建独立的 `.venv-linux` 并安装 Python 依赖；前端默认地址 `http://127.0.0.1:5186`，Python 服务默认端口 5187。Python 日志在 `service.log` / `service-error.log`。Ctrl+C 或 SIGTERM 会关闭本次启动的前端与 Python 服务；已存在且源码版本一致的 Python 服务会复用并保留。端口被旧版本或其他服务占用时启动失败，需先停止占用进程。

Linux 与 Windows 使用各自的虚拟环境；跨系统复制项目时不要复用 `node_modules`，应在目标系统重新运行 `npm ci`。登录配置仍使用未纳入 Git 的 `.env.local`。预载病例需另行复制 `public/preloaded/`，仓库不包含病例数据。

```bash
# 局域网访问前端；Python API 仍仅监听本机，通过前端 /api 代理访问
HOST=0.0.0.0 bash start.sh

# 构建并启动预览服务，默认端口 4186；同时启动 Python 服务
HOST=0.0.0.0 bash start.sh preview

# 单独运行 Python 服务，前台运行，可用于进程管理器
bash start-service.sh

# 自定义端口与解释器；前端 /api 代理自动跟随 Python 地址和端口
PYTHON_BIN=python3.12 PORT=8080 DENTAL_SERVICE_PORT=8081 bash start.sh
```

`HOST` / `PORT` 控制前端监听，`DENTAL_SERVICE_HOST` / `DENTAL_SERVICE_PORT` 控制 Python 监听，`PYTHON_BIN` 指定创建虚拟环境所用解释器，`DENTAL_VENV` 可指定虚拟环境目录（默认 `.venv-linux`）。直接使用 npm 启动时，可通过 `DENTAL_API_TARGET` 配置 `/api` 代理目标。`bash start-service.sh --check` 检查健康状态与源码指纹，退出码 0 表示版本一致、1 表示不可连接、2 表示旧版本或其他服务。

如需后台运行，可使用 `nohup bash start.sh preview >viewer.log 2>&1 &` 并记录 `$!`，停止时执行 `kill <记录的PID>`。预览用于部署验证；正式部署仍按下文配置静态服务与 `/api` 反向代理。单文件在线推理还需要 Linux 当前用户配置 OpenSSH、免密认证和 `DENTAL_SSH_HOST`，本地标签强平滑与预载病例无需 SSH。

## 使用

- 顶部步骤依次为模型预处理、分牙、初始位模型、治疗计划、目标位、分步、附件。目前实现模型预处理和分牙，其余步骤显示“该功能还在开发中”。
- 顶部工具栏保留网格、咬合碰撞；“调整模型”以蓝色按钮放在预处理画布右上方。咬合碰撞、调整模型仅提供开发中占位页面。切换步骤后返回模型预处理会保留已上传的模型、视角及网格状态；分牙入口会执行下述龈牙线强平滑处理。
- 默认无网格时使用 35° 视场角的透视投影。点击顶部“网格”开启正交投影及屏幕朝向的参考方格，再次点击恢复透视投影。切换保留观察方向、中心和目标平面的显示比例，不修改模型坐标；不同深度的牙齿会因投影变化而呈现不同的相对大小。
- 网格参照截图设计为浅灰细线与浅红粗线，覆盖画布及牙模；小格 1、大格 10 个模型坐标单位，不能自动认定为毫米。格线随正交缩放改变间距，过密细线会淡出。右下角标明投影模式与网格单位，导出 PNG 时包含已开启的网格。
- 左键拖动旋转，右键拖动按屏幕方向平移，中键拖动或滚轮缩放。滚轮向前放大。触屏单指旋转、双指缩放和平移。
- 采用固定竖直轴的环绕操作，旋转围绕可见模型中心；限制极点防止画面翻转，轻微阻尼平滑收尾。水平拖动从顶部视角仍围绕统一竖直轴旋转。
- 导入后默认按牙弓几何自动定向，无需分牙标签：等面积表面采样、空间分布主轴分析和 U 形牙弓拟合识别前方；双颌位置或已知颌面与开放表面法向确定上下。两颌共用刚性显示旋转，原始顶点坐标、牙号映射和咬合关系保持不变。无法可靠判断时使用基础 Z 轴显示并提示手动校准；半口、严重缺损或扫描边缘干扰仍需人工检查。
- 上颌面、正面、右侧、仰视、左侧、后视、下颌面按钮基于定向后的坐标切换视角。显示坐标的正面为 +Z、后视为 -Z；患者右侧为 -X、左侧为 +X。重置恢复当前病例的自动或已校准正面；上下颌筛选不重新估计方向。上下颌面保留极小倾角以避免极点奇异。
- 打开右上方模型面板可查看定向状态、重新自动定向，或将旋转后的当前视角设为正面。校准会同步更新全部快速视角，并在当前病例列表切换时保留；刷新或重新导入清除。仍可指定 Z/Y 轴向上，并用原有 X/Y/Z 轴旋转按钮辅助校正。单颌文件需正确指定所属颌面；封闭底座单颌的上下方向可能无法自动确定。
- “全颌”筛选上颌或下颌；每个图层可独立显隐、移除；单独上传模式可修改所属颌面，文件夹模式的颌面由文件名确定。文件名含 upper/maxilla/上颌 或 lower/mandib/下颌 时自动分类；其他文件需手动指定。
- 拖入一个或多个 ASCII/二进制 STL 或 OBJ，或在空白页面点击“单独上传 STL / OBJ”，支持混合选择。每次上传替换当前整批模型，同时选择的上下颌文件会一起保留；取消文件选择不影响当前模型。单文件最大 150 MB；读取失败显示提示并继续处理本批其余文件，全部失败时回到上传页面。上传成功后切换至全颌显示。连续上传时仅显示最新一批，旧批次未完成的读取不会重新加入场景。
- OBJ 文件内的多个网格分组归入同一图层，并保留原始坐标。支持三角面、多边形面和负索引；忽略点、线、MTL 材质和纹理，统一使用沙金色材质，不读取外部资源。只有点或线、不含表面的 OBJ 会提示无法显示。
- 平滑、原始面片和线框显示，透明度调节，Y/Z 向上选择，以及三轴 90° 旋转。方向操作对所有模型整体应用。
- 底部支持适应窗口（F）、恢复初始视图、导出 PNG 画布截图；右上角可以隐藏模型面板。

模型保留原始坐标及上下颌咬合关系，不单独居中。默认输入坐标 Z 向上、前牙朝 -Y；其他模型可调整整体朝向。STL / OBJ 没有可靠的标准单位信息，界面尺寸使用原始坐标单位，不能自动认定为毫米。透明模型交叠可能出现实时渲染排序误差。

## 预载数据

空白页面点击“加载预载数据 · 12 组案例”，或右上角“预载数据”，加载案例-01。左上角可切换案例-01 至案例-12。12 组均包含上下颌及已有分牙标签，按模型外观筛选为无明显固定托槽、弓丝，允许树脂附件；按源目录记录计数，未做几何去重。

模型按所选案例读取，不会一次下载全部数据。预载案例直接读取提前生成的强平滑结果，无需启动 Python 服务或重新计算；保留标签校验、FDI 配色、牙号和手工调整。结果缺失或损坏会提示错误并阻止进入分牙，不自动调用线上推理或重算。普通文件夹导入仍按原流程执行强平滑。切换案例会替换当前模型，刷新后可再次点击加载。

案例清单在 `src/preloaded-cases.json`。本机数据位于已忽略的 `public/preloaded/`，构建时 Vite 会复制到 `dist/preloaded/`，部署需保留此目录。数据与本机来源映射 `test-results/preloaded-source.local.json` 不纳入 Git。

预载分牙结果为每颌的 `.refined.bin.gz`，与模型一起打包。更新模型、标签或强平滑算法后，运行以下命令重新生成；脚本校验源文件及算法指纹，支持断点续跑。先生成全部结果，再构建部署。

```powershell
.\.venv\Scripts\python.exe scripts/bake-preloaded.py
npm.cmd run build
```

## 从本地文件夹读取已有分牙结果

在预处理点击“选择数据文件夹”，选择工作区 `排牙软件/data/瑞通平台自有数据` 整个目录（相对项目根目录为 `../data/瑞通平台自有数据`），也可以选择其中单个病例或 `obj` / `stl` 子目录。浏览器在本机读取模型和标签，交给本地 Python 服务执行龈牙线强平滑；文件夹模式不会请求线上推理。请用 `start.cmd` 一起启动前端与本地服务。

文件以 `_upper.obj` / `_lower.obj` 或 `_upper.stl` / `_lower.stl` 命名，并与同目录、同名 `.json` 配对。优先使用有完整结果的 OBJ；没有完整 OBJ 配对时可使用 STL。忽略 `_ul` 合并模型、`_only_tooth` 及 basics 文件，避免重复加载。选择数据总目录时，左上角提供病例切换，每次只显示一个病例的上下颌。

读取期间顶部“分牙”转圈，模型与标签校验完成后才允许进入。预处理保留原始网格和沙金色，分牙页面显示强平滑后的 FDI 区域及固定牙号气泡。缺失、损坏、无牙齿或顶点数量不匹配的结果显示具体错误，并阻止进入分牙；不会自动改用线上推理。文件夹模式的颌面根据文件名确定，不能手动修改。切换病例会清除旧模型，过期异步读取不会覆盖新病例。

空白页面保留“单独上传 STL / OBJ”入口，以下在线自动分牙仅适用于此入口或单文件拖入。

## 自动分牙

先启动本地适配服务，再启动前端。本机需要 Python 3.11+、`server/requirements.txt` 中的依赖和可免密访问客户服务器的 OpenSSH；GPU 和模型依赖使用服务器容器已有环境。

```powershell
python -m venv --system-site-packages .venv
.\.venv\Scripts\python.exe -m pip install -r server/requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app:app --app-dir server --host 127.0.0.1 --port 5187
```

也可双击 `start-inference.cmd`。前端开发/预览服务器将 `/api` 转发至 5187；生产部署需为同源 `/api` 配置反向代理。SSH 使用当前用户已配置的 `AI牙科客户服务器` 主机别名，认证信息不写入项目。

1. 在预处理上传上下颌 STL / OBJ。文件名无法判断颌面时，在模型面板手动指定上颌或下颌。
2. 上传完成后自动在后台依次调用 FPS 与 BDL 两阶段推理，顶部“分牙”步骤转圈，期间不能进入分牙界面，预处理视图仍可旋转和缩放。所有模型推理和强平滑完成后，顶部“分牙”步骤才可点击。失败时在预处理页面显示原因和重试入口；颌面未知时自动打开模型面板，指定完成后自动开始分牙。成功结果保留到本次模型被替换为止。重新上传会丢弃旧结果，旧请求不能给新模型着色。
3. 牙龈保持沙金色，牙齿按 FDI 牙号着色。11/31 使用同一套浅色，21/41 使用同一套深色，沿中切牙到后牙依次为蓝、紫、粉、绿、青、橙、蓝紫。点击“牙号”显示蓝色圆形标注和引线。气泡位置在模型坐标中固定，随模型旋转、平移和缩放，保持朝向屏幕；不做碰撞避让或贴边重排，允许重叠，颌面筛选仅控制显隐。气泡、文字、锚点和引线在三维场景中绘制，与牙模共用深度缓冲；牙模会遮挡后方的标注，包括气泡及引线的局部遮挡。
4. 完整上下颌结果可进入“调整分牙”，依次完成上颌分牙、上颌牙号、下颌分牙、下颌牙号。返回预处理恢复沙金显示，切回分牙复用当前页面的分牙结果。推理失败显示原因并提供重试。

### 手工调整分牙

预处理、分牙展示及调整分牙统一使用左键拖动旋转视角、右键拖动平移、中键拖动或滚轮缩放。编辑时命中控制点则左键拖点，圈选工具下左键绘制圈选，点击牙号气泡修改编号。龈牙线或控制点悬停时以亮绿（`#00FF00`）高亮，单击任意曲线或控制点即可选中其所属龈牙线，也保留 Ctrl＋左键点击牙齿选中。点击牙龈区域取消当前龈牙线选择；从牙龈区域拖动仍旋转视角。普通点击控制点只选择，不产生编辑历史；边界沿原有网格表面更新，不改变模型坐标或面片几何。正常龈牙线初次按弧长生成 20–25 个控制点，公共边界统一采样并共用重合控制点，重合位置只绘制一个点；顶点不足的微小边界保留实际可用点。拖动只更新现有控制点位置，拉长曲线不增加点，撤销/重做同步恢复点位；控制点按锚点判断遮挡，可见点显示完整不透明圆形，被牙模遮住的点整体隐藏且不可拾取。默认与邻牙联动；勾选分离公共点后仅调整当前区域，缩小时留下牙龈间隙，邻牙区域保留。取消勾选不合并已有间隙。删除曲线立即将整颗牙的区域归为牙龈。

切换牙齿圈选可增加或减去起点牙齿的范围，松开即闭合应用。按当前颌全部面片的中心投影选择，包含被遮挡的背面；增加可覆盖其他牙齿，减去仅将目标牙齿圈内部分归为牙龈。从牙龈或模型外开始不修改结果并显示提示。切换工具复用同一份面片归属。

牙号步骤点击三维气泡打开浮窗，可选择恒牙或乳牙编号；占用编号会交换；S 选择占用编号时，对方区域会变为 S，候选按钮提示该结果。B 与 I 互斥且可再次点击取消，标记随牙齿区域保留。S 删除原编号但保留独立区域与 B/I，重新编号可恢复普通牙身份。第三磨牙采用橙色以区别牙龈，继续保持 11/31、21/41 对应同色。下颌按 FDI 对应象限提供候选；乳牙复用对应象限前五牙的色板，S 使用紫色。

撤销和重做跨工具、跨四步连续保留，每次拖动、圈选或交换计一步；撤销后新编辑会清空重做。支持 Ctrl＋Z、Ctrl＋Y / Ctrl＋Shift＋Z，拖动手势期间屏蔽历史快捷键，松手后恢复。重置须确认，恢复本轮上下颌全部初始状态并清空历史。中间“保存并下一步”只保留草稿，退出确认会丢弃本轮所有修改。第四步保存确认后回到展示页，再次进入时以刚保存的结果为基线。保存仅当前页面有效，刷新或重新导入后读取原文件。

新增龈牙线、重新提交 AI、步骤下拉为禁用占位。后续节点重载、文件写回、导出和持久保存不在本阶段范围。病例完整性告警仍按需求文档记录为待修复事项。

适配层默认通过 SSH 调用 `tooth-3d` 容器的 `/opt/conda/envs/tgn/bin/python`，使用 `/home/yidong/ai-dental-orth/pathology_analysis/inference` 现有代码及 `models/ckpts/fps.h5`、`bdl.h5`。可通过 `DENTAL_SSH_HOST`、`DENTAL_CONTAINER`、`DENTAL_REMOTE_PYTHON`、`DENTAL_MODEL_ROOT` 环境变量修改配置。

现有 HTTP API 包含整套病理分析及持久化流程，没有独立模型上传分牙接口，因此本适配层直接调用容器现有 FPS/BDL 管线，只取分牙结果。执行代码经 SSH 命令传递，不安装远程文件、不修改源码、不重启线上服务，也不写入病例库或 MinIO。模型顶点压缩后通过 SSH 标准输入传输，临时 OBJ 在请求完成后删除。

## 龈牙线强平滑模块

本地标签与在线推理共用 `server/refinement/` 模块。在原始标签上清理小型封闭孤岛，提取牙龈/牙齿和牙间共享边界，将平滑线投影回原始牙面，求解边界带内的标签场，最后在原三角面中重新划分区域。参数复用已确认的强平滑：带宽 1.2、场平滑权重 6、曲线约束权重 16、曲线迭代 48、位移上限 0.55、孤岛面积上限 1。长度和面积均按原始模型单位计算。

`src/segmentation-refinement.mjs` 管理原始 OBJ 拓扑、二进制传输、面片着色和按面积计算牙号锚点。分牙展示独立修正网格，返回预处理使用原始网格；后续重新推理仍发送原始模型。不会写回上传文件或保存病例数据。

服务在本机串行处理强平滑，不调用 SSH。已将曲线投影改为每轮合批，真实样例每颌约 17–22 秒（随网格与本机负载变化，详见 `docs/refinement-performance.md`），期间可操作预处理视图，分牙入口保持忙碌。切换病例或重新上传会取消前端旧请求并忽略过期结果；已开始的 Python 运算会完成，之后处理新请求。服务不可用或几何检查失败会阻止分牙展示并提供重试。

修正前自动过滤叉积模长不超过 `1e-15` 或含长度不超过 `1e-12` 的边的退化三角面，并同步移除无面引用的顶点、重映射面索引和顶点标签。保留有效顶点原始坐标，不写回原始模型。过滤后无有效面或某个非零牙号完全丢失时才拒绝继续；无效坐标、索引和标签仍会报错。返回报告中的 `input_faces`、`filtered_degenerate_faces`、`input_vertices`、`removed_unreferenced_vertices` 记录清理数量，`source_faces` 为过滤后的有效面数。

`start.cmd` 自动创建独立 `.venv`、首次安装依赖并在后台启动 5187 服务，日志在 `service.log` / `service-error.log`。手动运行 `npm.cmd run dev` 时需要另启动上述 Python 服务。生产部署也需要本地处理服务和 `/api` 反向代理。算法仅对分牙边界进行几何修正，不包含解剖真值或临床准确性验证。

编辑性能：控制点使用 InstancedMesh 合并绘制，边界按区域缓存，面片或编号变化只更新受影响颌的颜色；编号/标记变化不重新提取边界。曲面拾取使用 three-mesh-bvh 的间接索引模式，不改变原始面片顺序、标签映射或几何坐标。步骤、工具切换会清除旧提示；无效拖动立即隐藏预览，松手不提交上一次有效位置。文件夹导入、单文件导入及病例切换均经过退出编辑确认。

处理诊断：强平滑响应报告包含 `stage_seconds`、`decode_seconds`、`curve_count`；响应头 `X-Refinement-Queue-Seconds` / `X-Refinement-Compute-Seconds` 区分排队与计算，详情写入 `service-error.log`。健康接口的 `revision` 为当前进程加载时的源码指纹，启动脚本发现与磁盘代码不一致会提示重启本机服务，避免修改 Python 后继续使用旧进程。
