## 2026-10-13 手工调整分牙

依据 `docs/adjust-segmentation-requirements.md` 在 `dev-fenya` 实现完整双颌四步流程。编辑数据与显示颜色分离：强平滑响应保留逐面标签，进入编辑后建立稳定区域 key、面片归属与编号/特殊标记元数据。S 的编号为 null，原 FDI 不另存；B/I 随区域保留。

- `src/segmentation-editor.mjs` 精确焊接重复三角面顶点，提取区域闭合边界，沿表面边网格寻路替换拖点两侧曲线，再由边界切分面片连通域更新归属。拖动预览也沿原表面网格；几何坐标、原始网格及上下颌关系不改变。分离模式不覆盖邻牙，缩小部分归牙龈，取消勾选不合并。
- 圈选按当前颌全部面片中心的屏幕投影处理，包含背面；增加覆盖其他区域，减去仅处理起点牙齿。所有工具由同一份面片归属重建边界与颜色。分辨率受原网格限制，不另做曲线平滑；不能形成有效闭合边界的拖动保持原状态并提示重试。
- `src/adjustment.ts` 管理 Ctrl 选牙、表面控制点拾取、四步顺序、当前颌视角、编号浮窗、互斥 B/I、S 转换与确认框。牙号仍为参与深度遮挡的固定三维气泡。编辑时左键选择/编辑、右键旋转、中键平移、滚轮缩放。
- 差量历史覆盖上下颌面片和元数据，整次拖动、圈选或编号交换计一步，跨工具及步骤保留。新编辑清空重做；重置恢复本轮双颌基线并清空历史；退出丢弃本轮；末步确认保存后下轮使用新基线。顶部步骤跳转与拖入替换模型也经过退出确认。
- 新增曲线、AI 重提、步骤下拉保持禁用占位。没有文件写回、持久化、后续节点重载或单颌流程。病例完整性告警 Bug 仍待处理。

未定细节的实施取值：下颌恒牙为 31–38 / 41–48、乳牙为 71–75 / 81–85；乳牙复用对应象限前五牙色板，圈选中的 S 为紫色；B/I 跟随区域，交换编号不交换标记；重置保持当前步骤、工具、相机。这些是当前实现选择，不将其写作截图已确认结论。

验证：`npm.cmd test` 35 项通过，`npm.cmd run build` 通过（仍有 Three.js 包超过 500 KB 的原有提示）。新增 10 项核心测试覆盖表面边界与邻牙联动/分离、圈选覆盖/减去及背面穿透、S 无旧编号身份、编号交换、标记互斥、双颌整体撤销/重做分叉与下一轮基线恢复；强平滑测试另检查返回标签独立于响应缓冲区。
